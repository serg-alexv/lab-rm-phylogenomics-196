The primary route is serial: finish the actual operational gates, build one explicit resource config, execute one approved genome, measure its real footprint, curate that closed checkpoint, then preserve and independently verify its recovery archive before proceeding to a storage-limited queue. The unchanged approved196 panel and accepted Stage2/3 source receipts gate native searches; the final host tree is absent from successful-genome identity. Final full196 matrix/tree join and Stage6 still require their accepted host tree and the separate published-tree workflow gate.

This package prepares source and own C synthetic tests only. It does not assert a new successful runtime/storage/interop/native/curation/archive gate. Root's actual separately published receipts determine current operational readiness. Current source pins and preserved drafts appear in `stage5_closed_genome_archive_preparation.json`. Sources remain C-only; root alone publishes or invokes actual owners.

## Independent recovery and eviction boundary

`stage5_closed_genome_recovery.py` is a separate producer-independent API, without download/CLI/native/adoption/deletion. `verify_archive(path, outer_sha, complete_sha, accession, check)` checks the actual outer bytes, exhaustive member CRC/SHA/SUMS, original selected V2 complete payload, fixed panel/source/runtime bytes and original owner/status/proof joins. `restore_fresh(...)` creates only a NEW tree and reopens every byte/mode/mtime plus directory/empty-guard inventory; it refuses existing destinations, unresolved privilege bits, drive/ADS names and traversal paths. Its result explicitly leaves canonical cache adoption, curation and remote recovery untested. Callers must own cold exclusivity, finite resources/deadline and the storage proof. It does not replace the retained native/curation validators.

Before any eviction, root must publish immutable source/index/control bytes, upload the exact asset/sidecar, perform a fresh independent complete remote download/readback, and prove exact canonical rehydration under the real storage/lock/runtime gates with the retained readers. Native receipt absolute paths and curation `evidence_roots` require the original canonical bind path; a different staging root alone is insufficient. Keep originals while a new restored tree is compared, and preserve all curation/review witness archives separately. This package contains no purge, original move/delete, remote controller or canonical restore owner. Host-wipe authority remains absent.

For the196 queue, retain at most one unarchived closed genome while establishing actual footprint; process light review between closed checkpoints, and checkpoint publication per genome/bounded batch. Do not launch an unbounded full196 queue before storage recovery is demonstrated. Primary storage reduction is compression plus verified remote recovery and independently validated canonical rehydration, followed only by a separately reviewed exact-leaf eviction. If any genome exceeds the finite single-asset/count/time limit, the bounded fallback is to preserve it and implement a same-layout indexed multi-asset split from measured outputs; no cap override, missing-member publication or automatic continuation. Existing raw checkpoints are never rerun merely to make packaging easier.

Original source headers remain unchanged. Before a public raw release, root must review actual archive member kinds and retain/reference original upstream notices for any copied model/source material; the separately recovered component assets still have their explicit notice/source-coverage limitations. Logical bytes are not a claim about measured physical disk reclamation. No archive acceptance authorizes biological absence, source eviction, cleanup of unrelated caches or deletion of the retained runtime image.
