# Installed Stage5 runtime recovery: preparation scope

The primary recovery method is a complete logical copy of the three actual installed roots at their original Linux prefixes: `detector_env`, `defense_models`, and `padloc_db`. It preserves installed Conda/pip/R files, local modifications, original notices, exact regular bytes, symlink text, internal hardlink groups, modes, UID/GID, nanosecond modification times, and xattrs in the manifest. The already verified 339 original Conda archives are complementary evidence; their verification does not establish recovery of the installed environment.

The five frozen contract/plan files remain unchanged. Three additional inactive functions now cover future full inventory/capture, independent complete payload reading, and read-only comparison of a disposable restored tree. They provide no standalone capture, readback, extraction, or restoration command. All actual runtime inventory, public byte/notice review, capture, fresh remote payload readback, extraction, restoration, and runtime equivalence checks remain **NOT_RUN**. No image bytes were read for this preparation. The protected 8 GiB ext4 image is retained unchanged.

The inventory uses no-follow traversal and records every selected node, including otherwise unselected installed files. Hardlink groups are normalized after final canonical ordering, so the first canonical path is the regular-file witness and all aliases point backward to it. Secret screening includes regular bytes, pathname strings, symlink targets, and xattr names/values. Screening emits reason codes only and supplements an actual whole-file public review. Private or ambiguous required files block complete public capture; the code does not silently omit them or redact original bytes.

Capture requires exact actual runtime/full-inventory/public-review/notice/cold-closure pins, the original WorkflowLock proof, exclusive backing-image writer exclusion, a current read-only ext4 mount with no writable aliases or escaping nested mounts, and a separately reviewed existing-owner admission callback. It streams one gzip/PAX tar into compressed shards of at most 448 MiB, with 256 KiB copy chunks and a 1,800 second internal deadline. The callback must continuously enforce current physical and commit reserves of at least 1,536 MiB, owned lifecycle and finite overall deadlines. The current files do not implement that Windows owner adapter. Metadata objects are bounded but held in memory in parts of the producer/checker; constant process memory is not established and actual metadata needs must pass admission.

The independent reader imports no producer. It checks each shard and the entire compressed stream, one gzip stream including CRC/EOF, exact tar members and all regular bytes, exact manifest/control hashes, POSIX/link metadata, and the complete actual scientific-runtime subset through captured links. Its successful local status explicitly says **FRESH_REMOTE_NOT_PROVEN**. A future owned-download adapter must independently bind published source commit, Release tag/asset identities, exact index and sidecars, actual fresh download bytes, and stable before/after remote metadata. No local-cache substitute establishes that gate.

The cold checker accepts only a new disposable `/var/tmp/lab_rm_runtime_restore_<unique>` tree on actual ext4. It compares the exhaustive restored path set, all bytes and metadata, exact symlink text, xattrs and internal hardlink equivalence. Fresh regular link counts must equal captured scoped group sizes, excluding restored external aliases. Source inode/birth/ctime and the original block image are provenance, not properties recreated by logical recovery. It performs no extraction, installation, mount, package execution or native inference.

The remaining operational prerequisites are explicit:

1. Root must obtain the actual pinned runtime manifest, full installed inventory, OS/dependency/ambient-context fingerprint, whole-file public scope review, and license/source/notice review under the existing owner. Pending preparation inputs cannot authorize capture.
2. Root must integrate the inactive functions with the existing finite owner/lease/resource/closure protocol, publish the exact reviewed source, and run bounded synthetic archive/restore fixtures before production capture. Current tests exercise pure metadata and byte-block predicates only.
3. A safe cold extractor is still pending. It must avoid generic `extractall`, use a new ext4 target, prohibit path/type/link escapes, create only reviewed nodes, restore xattrs/ACL/capability metadata explicitly from the manifest, and preserve hardlink and directory-mtime ordering. Publication/readback and cold extraction are distinct gates.
4. After full fresh remote payload verification and cold-tree comparison, a separately owned cold test must restore the original prefixes and verify the actual pinned scientific runtime plus external dependencies and relevant existing benign fixtures. Absolute shebangs, installed-prefix references, Ubuntu loader/glibc/OS ABI, locale, and external R/config dependencies are not preserved solely by three-root bytes.

No installed-build equivalence, scientific acceptance, eviction authorization, or host-wipe authorization is granted by this preparation. Retain the original runtime and all recovery inputs until the separate operational and restoration gates actually pass.
