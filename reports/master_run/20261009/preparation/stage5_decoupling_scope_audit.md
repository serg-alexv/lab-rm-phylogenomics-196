# Stage5/6 dependency and overlap audit

2026-10-09. Source/read-only audit in C work; no code edits, WSL start, G execution/write, detector search, native fixture, publication or cleanup. Current source pins are below. Root owns live Stage4 state, current remote reconciliation and resource measurements.

**Conclusion:** native Stage5 and per-genome curation need the fixed approved196 genomes and accepted sequence/locus inputs, not the final host phylogeny. Current Stage5 final-tree coupling is an orchestration choice. Remove that scientific dependency in prepared code. Keep final accepted/published tree requirements for the actual tree/matrix join and production figure. An early IQ-TREE tree/checkpoint is not an accepted host tree or a finished biological input to Stage5.

**Primary route:** preserve the sole running IQ-TREE attempt and its existing lock. During it, overlap light accepted-source/context and methodological review, source preparation, and Stage6 artifact/interface work. After exact owned native closure and lock release, run the actual WSL/lease/pidfd/storage fixtures; pin the retained runtime/configuration; measure one bounded approved-genome run as the first real member of the196, retaining its full-scope result. Continue one native genome worker with light independent curation of each completed immutable genome in parallel. This route waits for operational availability, not Stage4 success/publication. A failed Stage4 can leave Stage5 progressing after proven closure. Final join/render waits for accepted/published Stage4 plus independently accepted curation.

**Fallback:** if actual lifecycle, mount, reserve or measured detector envelope fails, emit the genuine bounded deferred/failed state, preserve successful caches and unknown closure evidence, and continue light source/review work. Reconfigure resources only within current authority and then retry the unfinished genome with unchanged scientific inputs. Do not blindly add heavy workers, truncate models, shorten searches or convert missing results to zero.

## Operational overlap is a separate gate

- `stage5_windows_owner.py:127` acquires the original `A.WorkflowLock`; `atomic_iqtree_windows.py:264` locks the same original byte and exact file identity with nonblocking exclusive locking. The current native IQ-TREE owner holds it. A second Stage5 owner cannot legitimately acquire it now. A declared lease `workflow_lock_held=true` cannot substitute for that ownership.
- `stage5_atomic.py:381` also takes global `.native_runner.guard` plus genome `.guard`. `run_genome:408-411` rejects any unresolved launch intent/native closure across the whole output root. These enforce one native Stage5 worker and forbid naive multi-process per-genome launches. Keep them for the primary route.
- The existing Windows owner loops serially over the approved panel, maintains exact birth/exit/nonce bindings and renews actual resource leases. Independent per-genome curation can consume a complete immutable checkpoint while the worker searches a different genome. It must use a separate output namespace and must not modify native receipts/cache.
- Actual Windows-to-WSL lease expiry, pidfd/subreaper escaped-descendant closure and filesystem lifecycle fixtures remain `PREPARED_NOT_RUN` in current preparation receipts. Actual ext4 bind proof/UNC equivalence also remain NOT_RUN. Historical executable/version probing does not establish these lifecycle behaviors.
- The initial config still has null incremental Windows, commit, Linux, address-space and sampled-RSS requirements. They need measured or explicit conservative finite values before `load_config` accepts run. Keep1.5GiB Windows reserve, actual C/G free-space checks, Linux reserve, finite command/job/cleanup waits and exact owned closure. The active IQ-TREE cap/reserve and WSL VM overhead must be counted in any concurrent budget.
- Existing root probe confirmed retained Python3.11.17/PADLOC2.0.0/R4.3.1/HMMER3.4/DF3.0.0/MacSyFinder2.1.4/pyhmmer0.12.3/pyrodigal3.7.1. No missing package has been established. Fresh actual runtime and effective MacSy configuration/native-library pins remain required; no install/upgrade is proposed.
- Full detector peak aggregate resident/commit usage, runtime and output volume are unmeasured. Per-process RLIMIT_AS is not an aggregate subtree cap. Current monitoring is a sampled stop, so sizing must retain margin. One measured worker is the admissible starting point. Only a later explicit policy/owner change plus measured safe headroom can justify one additional bounded worker; a large worker swarm is unsupported.
- The ext4 bind strategy preserves canonical lexical input/output/cwd/cache paths and native provenance. Preserve that scoped proof and UNC owner view. Full-panel file growth is estimated in the existing I/O review at millions of small files; physical free space must not be inferred from virtual ext4 capacity or logical hash-read volume.

Starting a native detector concurrently with the presently immutable IQ-TREE owner would require a real shared authority/admission protocol (or a controlled owner handoff), plus live lifecycle/combined-resource evidence. Merely deleting the final-tree check, dropping the original lock or creating a second lock is not enough. This is outside the minimal source-only decoupling and should not be introduced invisibly into the running attempt.
