# Stage6 prepared interface - not a scientific result

All code and fixtures are confined to this chat's `work/`. No real phylogeny or R-M matrix has been rendered. No WSL boot, installation or G repository write was performed for this preparation.

`stage06_render.py` accepts explicit `--tree`, `--matrix`, `--state`, `--approved`, `--join`, `--tree-validation`, `--curation-validation`, `--curation-source-manifest` and a new `--output` directory. Production requires the independent tree receipt `scientific_state=COMPLETE_VALIDATED`, exact tree/panel SHA256, and `join_validation.json` status `PASS_EXACT_196_784_JOIN` with exact tree/matrix/state/panel hashes,196unique tips/rows and784cells. All membership checks use accession keys. The approved production panel requires versioned GCF labels. Synthetic certificates require explicit `--synthetic`, carry different statuses and cannot authorize production.

The accounting-only join cannot establish scientific curation. Separate curation receipt schema is `RM_INDEPENDENT_CURATION_ACCEPTANCE_V1`, status `PASS_INDEPENDENT_RM_CURATION`, `dataset_kind=PRODUCTION`, `accepted_curation=true`,196accessions/784cells and exact matrix/state/panel hashes. It must affirm `all_actual_review_records_checked`, `source_native_bindings_verified`, and `complete_and_partial_architectures_checked`; `functional_activity_claim=NONE`. Its `curation_source_manifest_sha256` must match the supplied detailed source/model/code/review manifest, copied into the export. No actual production curation certificate exists at preparation time. Synthetic fixtures carry `PASS_SYNTHETIC_CURATION_CONTRACT` and `accepted_curation=false`. Honest scientifically reviewed uncertainty remains permissible and grey; acceptance does not establish activity or resolve every type.

An expressly qualified production alternative is `PASS_INDEPENDENT_RM_CURATION_WITH_DOCUMENTED_EXCEPTIONS`, with the same gates plus positive `documented_exception_count` and `--exception-manifest` pinned by `exception_manifest_sha256`. Exception schema `RM_DOCUMENTED_CURATION_EXCEPTIONS_V1` binds the approved panel and1-196unique approved accessions, each with FAILED_FATAL/FAILED_RETRYABLE/DEFERRED_RESOURCE/NOT_RUN execution state, reason, source/exception/current-terminal receipt hashes (terminal may be null only for NOT_RUN) and accepted-positive count. Exact detailed semantics remain the independent scientific checker's responsibility. The exception manifest is copied and hashed, and title/footer explicitly qualify the figure. This certifies honest panel accounting; it never asserts that an excepted detector search completed. No exception manifest is accepted for the ordinary no-exception PASS status. The primary execution path still aims for all196successful searches.

Both production curation statuses additionally require `operational_closure_verified=true`. `ACCOUNTED_RM_CURATION_WITH_UNPROVEN_OPERATIONAL_CLOSURE`, with `accepted_curation=false`, may preserve honest NA accounting but cannot authorize a figure. Frozen independently reopened positive checkpoints may establish a1inside an otherwise excepted genome; an unproven owned native scope remains a publication veto.

Matrix columns: `accession,Type_I,Type_II,Type_III,Type_IV` (tab separated), values exactly `1,0,NA`. Long state columns: `accession,rm_type,state,complete_count,partial_count,candidate_count,search_complete,conflict,positive_invalidated,count_lower_bound,review_ids`; rm_type values are exactly I,II,III,IV and use an explicit lookup to matrix columns. Booleans accept True/False (case insensitive) or1/0. `review_ids` is an explicit JSON list, with `[]` for no reviews. A1requires at least one unambiguously accepted complete predicted locus and `positive_invalidated=false`; another partial or unresolved candidate may coexist and remains in the state/count table. A0requires the explicit `NOT_DETECTED_AFTER_SUCCESSFUL_SEARCH` state, successful complete searches, zero complete/partial/candidate counts, no conflict/review and no lower-bound caveat. NA remains grey without imputation. The independent scientific curation checker, rather than this renderer or an accounting-only join, decides whether a cell is biologically supported.

The single vector scene retains input child order and every edge, with radial distances scaled linearly from original branch lengths. No reroot, sorting, pruning or support-based collapse is performed. Original Newick bytes are copied intact. NEXUS embeds the same tree with `[&U]`. The circular layout uses the existing serialization anchor solely for display and prominently states that the host phylogeny is unrooted. Internal support labels remain in the original tree and branch mapping; they are not overprinted onto a dense circular figure. Circular connection arcs and dashed tip leaders are display geometry. Root stem, if supplied, is recorded separately and is not an incoming phylogenetic edge.

Rings inner to outer: I, II including IIG, III, IV. Type colors distinguish accepted complete predicted architecture; white means screened nondetection; grey means unknown/incomplete/unresolved. `cell_mapping.tsv` records every cell, its accession/type/state/count caveats, ring, angle and color. `branch_mapping.json` records input lengths and descendant sets. SVG and PDF are drawn from the same `scene.json`, whose SHA256 is embedded in both. `provenance.json` pins all inputs, certificates, outputs and renderer/runtime versions.

The separate `check_stage06_outputs.py --output <render-dir> --report <new-report.json>` checks input/output hashes and acceptance bindings/counts, exact tip/cell/state/count/review mapping and palette, SVG/scene coordinates, every edge's radial length, every actual PDF vector path coordinate and polygon fill, exact PDF vector text/page/cell counts, unchanged Newick/NEXUS export, and complete iTOL state coverage. It does not independently establish biological acceptance; that remains the supplied receipts. The PDF is rendered with bundled Poppler and visually inspected as a separate step. Final scientific publication still requires actual accepted inputs, checker pass and visual review of that figure.

The retained environment was inspected before selecting a renderer. Native `C:/Program Files/R` was absent; retained code references `.tools/linux/detector_env/bin/Rscript` and an r-base4.3.1 Linux detector environment, rather than a ready Windows plotting stack. No native R/ggtree readiness was established. To avoid booting WSL or installing packages during the sole IQ-TREE job, the bounded fallback uses Python standard-library tree/layout/SVG code and the existing bundled ReportLab/PyPDF runtime for vector PDF creation/inspection. A future R implementation may replace the renderer only with the same acceptance, mapping and topology/length contract.

iTOL primary documentation consulted:

- <https://itol.embl.de/help/dataset_binary_template.txt>: BINARY1fills,0is empty and-1completely omits the cell. This format alone cannot show grey NA.
- <https://itol.embl.de/help/dataset_color_strip_template.txt>: COLORSTRIP permits an explicit color for every accession. `COLOR_BRANCHES=0` prevents coloring phylogenetic branches from ring values.
- <https://itol.embl.de/help.cgi>: circular phylogram/branch-length and leaf-order settings.

The intended iTOL figure uses the four numbered full-state COLORSTRIP datasets, ordered01to04 from inner to outer, with present/white/grey colors for every tip. A separate BINARY convenience export maps NA to-1and explicitly warns that unknown cells disappear. Use the four full-state strips for a four-ring publication view; do not substitute the binary export alone when unknowns exist or stack both formats as eight rings. No iTOL account upload, server import or GUI rendering was performed.

The small 4-tip fixture exercises mixed states, unequal/zero branch lengths, paired support strings and reversed matrix order. The current explicitly nonbiological 196-tip fixture uses `TEST_00000001.1` through `TEST_00000196.1`, rather than approved accessions, solely to assess dense label layout and all 784 cells. These IDs have the same character count and near Helvetica advance width as versioned GCF accessions: at 12 pt, a TEST label is 100.728 pt wide and `GCF_000000001.1` is 102.060 pt. Older fixtures with longer `SYNTHETIC_TIP_001` labels are preserved as preparation history. No fixture carries a phylogenomic or R-M conclusion.

Typography is designed for 180 mm print width. The 1100 by 1180 pt source page uses 12 pt tip labels (5.566 pt at print width) and 11 pt annotations/legends (5.102 pt at print width). Tip text is vertically centered on the unchanged radial anchor using explicit Helvetica ascent/descent metrics, avoiding the flipped-baseline collision at the north seam. Only header/footer positions and page height changed; all phylogenetic edges, connectors, leaders, ring coordinates and colors remain identical. Conservative rotated text rectangles must fit the page and avoid other text and legend swatches before output creation. This guard applies to actual future production labels too. The independent checker reopens SVG font/position attributes and PDF font sizes, text matrices/anchors and metric bounds; serialization drift, clipping and overlap are vetoes.
