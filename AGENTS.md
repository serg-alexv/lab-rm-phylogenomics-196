# Project execution rules
Read WORK_ORDER.md and STATUS.md before acting. The human has approved full196 sequence analysis and automatic stage progression. NO pilot biological panel and no routine approval pause. This supersedes historical G0 PENDING labels without modifying historical files.
All work runs on WD; GitHub serg-alexv/lab-rm-phylogenomics-196 is the canonical collaboration repository. Preserve raw NCBI evidence separately from interpretation. Never publish claims without executed evidence, never silently drop/replace genomes.
Use one production runner/writer lock. Inspect active work before launching. Limit concurrency to actual free RAM; no killing unrelated processes or rebooting. Use approved installed authentication; never print tokens.
After each stage: independent validation -> portable artifacts and report -> GitHub commit/release upload -> remote verification -> next stage automatically. Failures must be explicit. STATUS.md must reflect actual running/completed/not-run states.
Portable files: TXT/MD,TSV/CSV,FASTA,CLUSTAL,Newick,NEXUS,GFF/GBFF,SVG/PDF/PNG. Large data through standalone ZIP Release assets with hashes, not Git LFS pointers only or giant Git blobs. Keep current stage manifests stable and separate from mutable status/publication receipts.
Only methods, commands, measured resources, checks, decisions and concise rationale summaries belong in public artifacts. Hidden reasoning, raw private Codex event/session logs, secrets and unrelated user files must not be uploaded. Keep .private_run/ ignored.
Use exact assembly+replicon+locus keys, not WP protein ID alone. Preserve detector replicon boundaries/order. Report prediction separately from demonstrated function and successful non-detection separately from failed/not-run.
Never force-push, silently rewrite history, reduce tests, or change approved scope for cosmetic reasons. Later user corrections on main take priority; inspect them between stages. Scientific blockages need evidence reports, not fabricated completion.
